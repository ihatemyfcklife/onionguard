The Tor Problem vs The OnionGuard Fix Paradigm Shift

Standard web application firewalls (Cloudflare, AWS WAF, Fail2ban) assume every visitor has a unique client IP and can execute complex JavaScript challenges. On Tor, these assumptions destroy your service.

Broken Assumptions of Conventional Security

  • ×

    No Client IPs

    All traffic exits locally from the Tor daemon (127.0.0.1 or a Unix domain socket). Any IP-based rate limiting or banning accidentally blacklists your entire userbase at once.

  • ×

    No JavaScript

    Security-conscious visitors use Tor Browser at the Safest security level where JavaScript is strictly disabled. Cloudflare Turnstile, reCAPTCHA, and JS crypto puzzles render your site completely unreachable.

  • ×

    Fingerprinting Harms Privacy

    Canvas inspection, audio API probes, and browser fingerprinting actively violate the anonymity promise of the Tor network and trigger Tor Browser anti-tracking defenses.

Quick Start Implementation

Integrate OnionGuard with your standard Go net/http server in fewer than 20 lines of code. Works seamlessly with any Go framework (Chi, Gin, Echo, or standard Mux).

main.go
Go 1.22+ Standard Library 
package main

import (
	"fmt"
	"net/http"
	"time"

	og "github.com/ihatemyfcklife/onionguard/pkg/onionguard"
	middleware "github.com/ihatemyfcklife/onionguard/pkg/middleware"
)

func main() {
	// 1. Load baseline config with Wait Room & pure Go CAPTCHA enabled
	cfg := og.DefaultConfig()
	cfg.WaitRoom.Enabled = true
	cfg.Captcha.Enabled = true
	cfg.Captcha.MaxAttempts = 3
	cfg.RateLimit.AnonymousRate = 10 // req/min per anonymous circuit

	// 2. Initialize the OnionGuard defense engine
	engine, err := og.New(cfg)
	if err != nil {
		panic(fmt.Sprintf("failed to initialize onionguard: %v", err))
	}
	defer engine.Close()

	// 3. Define protected application handlers
	mux := http.NewServeMux()
	mux.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/html; charset=utf-8")
		fmt.Fprintf(w, "<h1>Protected Onion Service</h1><p>Zero-JS, Zero-IP verified.</p>")
	})

	// 4. Wrap your router with OnionGuard admission control middleware
	protectedHandler := middleware.Middleware(engine)(mux)

	server := &http.Server{
		Addr:         "127.0.0.1:8080", // Local Tor reverse proxy binding
		Handler:      protectedHandler,
		ReadTimeout:  5 * time.Second,
		WriteTimeout: 10 * time.Second,
	}

	println("[OnionGuard] Engine active. Listening on 127.0.0.1:8080")
	if err := server.ListenAndServe(); err != nil {
		panic(err)
	}
}

Tor Deployment torrc configuration

Route traffic from the Tor network to your local OnionGuard instance by configuring your daemon's torrc file.

/etc/tor/torrc
Tor v3 Onion Service 
# ===================================================
# Onion Service v3 Configuration
# ===================================================
HiddenServiceDir /var/lib/tor/my_onion_service/
HiddenServicePort 80 127.0.0.1:8080
HiddenServiceVersion 3

Local Loopback Isolation

Ensure your Go server only listens on 127.0.0.1 or an internal Unix domain socket. Never expose OnionGuard directly to public IPv4/IPv6 interfaces.

Directory Permissions

Tor requires strict permissions on the keys directory: chmod 700 /var/lib/tor/my_onion_service/. The onion address will be stored in hostname.
